# AI Reel Factory -- Design & Architecture

## Core Concept

The speaker should **not always be on screen**. The editing plan alternates between A-roll (talking head) and B-roll (AI-generated clips matching the script). Filler words are covered with B-roll and muted audio so the video stays synced and clean.

---

## Sync Strategy

- Filler words are **not cut** from the timeline (that would desync lips with audio).
- During filler segments, B-roll is **overlaid** on the video track and audio is **muted**.
- The viewer sees B-roll and hears silence instead of "um/uh".
- B-roll overlays use `tpad` for frame-level time alignment in FFmpeg, avoiding the classic overlay timing bug where frames get consumed early.

## LLM Integration (Gemini)

Both the script and editing plan are generated by Gemini via a shared client (`script_engine/llm.py`).

**Script generation**: `prompts/script_generation.txt` + topic + references (`hook-patterns.md`, `writing-styles.md`, `viral-angles.md`) + style guide -> Gemini -> markdown script.

**Editing plan**: `prompts/editing_plan.txt` + script + references (`visual-patterns.md`, `writing-styles.md`) + style guide -> Gemini -> JSON with beats. Each broll beat's `suggestion` follows the format: `"[Subject action]. Camera: [one move]. [Scene detail]."` This structured format produces better search results on Pexels and better Veo output than stacking adjectives.

**Aroll-first hook**: The editing plan always starts with an aroll beat (speaker face-to-camera). This is enforced both in the prompt and via `_enforce_aroll_start()` post-processing -- if Gemini starts with broll, a 4-second aroll is inserted at the front.

**Fallbacks**: Both stages fall back gracefully if the API is unavailable -- script returns a placeholder, editing plan returns an all-aroll beat.

---

## Reference Materials

Files in `references/` are loaded and injected verbatim into Gemini prompts:

- **Script generation** receives: `hook-patterns.md`, `writing-styles.md`, `viral-angles.md`
- **Editing plan** receives: `visual-patterns.md`, `writing-styles.md`

This means the LLM actually reads and follows your hook formulas, anti-slop rules, B-roll ratio guidelines, and editing pacing rules -- not just vague instructions to "make it good."

---

## Style Guide System

`style_guide.json` at the repo root defines global defaults. A project can override by placing its own `style_guide.json` in the project folder (keys are merged, project wins).

The style guide feeds into three places:
1. **Gemini prompts** -- script and editing plan get style context
2. **Veo prompts** -- every B-roll clip gets the style as a suffix
3. **Filler clip** -- the `filler_clip` field defines the neutral B-roll prompt

## B-roll Overlay Timing (FFmpeg)

The overlay filter in FFmpeg consumes frames from all inputs simultaneously. Without proper timing, a B-roll clip scheduled for t=30s would have all its frames consumed by t=8s (while `enable=false`), leaving only a static last frame.

**Fix**: Each B-roll clip gets `tpad=start_duration=X:color=black` prepended, creating black padding frames from t=0 to the overlay start time. Combined with `enable='between(t,start,end)'`, the black frames are never shown, but they prevent premature frame consumption. `eof_action=pass` ensures the base video shows after each overlay ends.

---

## B-roll Sourcing

The broll stage (`video_engine/broll.py`) sources clips in priority order:

1. **Existing clip on disk** -- if the file already exists, skip (avoids re-downloading/regenerating)
2. **Pexels stock video** (`video_engine/pexels_client.py`) -- free, searches by auto-extracted keywords from the suggestion. `extract_keywords()` strips camera/scene directions and keeps 2-4 subject words.
3. **Veo AI generation** (`video_engine/veo_client.py`) -- paid fallback, only used when Pexels returns no results and `BROLL_USE_VEO` is not `0`.

## Key Technical Decisions

| Decision | Rationale |
|----------|-----------|
| Pexels-first B-roll | Free stock video covers 80%+ of broll needs; Veo only for creative shots |
| Overlay, not concat | Preserves original audio timeline; simpler to mute specific ranges |
| tpad for timing | Reliable frame-level alignment without PTS manipulation |
| fade=color=white for flash | Much faster than geq (no per-pixel processing on every frame) |
| fade=color=black for transitions | Visible transitions without alpha channel complexity |
| 1.2x speed | Faster pacing for short-form content; applied via setpts + atempo |
| Aroll-first hook | Speaker face grabs attention; enforced in code even if LLM ignores prompt |
| Reference injection | LLM reads actual hook/style/angle docs, not vague instructions |
| Subject/Camera/Scene prompts | Structured format works well for both Pexels keyword extraction and Veo |

## Clip Naming

Raw clips: `01.mp4`, `02.mp4` (merged in filename sort order).
B-roll clips: `001.mp4`, `002.mp4`, ... (numbered by broll_index from timeline). `filler.mp4` is reused for all filler segments.

## Design Assessment: Video Generation Flow

**Verdict:** The overall flow is right. Pexels-first → Veo fallback, overlay timing with tpad, and the Subject/Camera/Scene suggestion format are solid. The main lever for better output is **Veo prompts**.

**Why the flow works:**
- One suggestion string serves both Pexels (keywords) and Veo (generation), so the editing plan stays simple.
- Style guide is already applied as a suffix to every Veo call.
- Cost control (Pexels first, BROLL_USE_VEO=0) is built in.

**Two Veo prompting modes:**
- **Cinematic mode (default)**: Uses the style guide as-is to generate more neutral/\"cinematic\" B-roll. Prompts are built from the editing-plan suggestion plus style suffix, with explicit clip duration framing.
- **IG kinetic mode (opt-in via `VEO_KINETIC_IG=1`)**: Optimized for fast, high-energy Instagram B-roll. Prompts become more aggressive, subject-in-motion first, with strong camera movement and motion keywords.

**Kinetic Veo prompt architecture:**
- **Subject in mid-action first**: Start in media res (e.g. \"A person sprinting through a crowded street\"), not static poses. This comes from the editing plan's `suggestion` text.
- **Scene/setting second**: Append where it happens (e.g. \"neon-lit city at night, wet pavement reflecting lights\").
- **Kinetic camera third**: Explicit, energetic camera language derived from the `Camera:` part of the suggestion (e.g. \"Camera: whip pan tracking closely\").
- **Style/energy suffix**: Style guide suffix adapted for kinetic mode (drops slow/floaty words, keeps realism/aspect ratio, and injects speed words like \"hyper-kinetic, fast shutter, high-speed dynamic movement, high energy\").
- **Explicit temporal frame**: Every Veo call is framed as a `Single continuous N second clip`, helping the model treat it as one flowing shot.

**Style guide handling in kinetic mode:**
- `style_guide.json` stays the single source of truth; we **do not mutate** it on disk.
- `_build_style_suffix(style, kinetic=True)` adjusts output only at prompt-build time:
  - **Negative `avoid` text** is never injected into the positive prompt string in kinetic mode (avoids \"avoid X\" backfiring).
  - Slow/floaty adjectives like \"cinematic\", \"smooth\", \"sweeping\", \"dreamy\", \"slow-motion\" are filtered or replaced with fast, gritty language.
  - A kinetic tail is added: `motion blur, high-speed dynamic movement, fast shutter, hyper-kinetic, high energy`.

**Gemini expansion guardrails:**
- `_expand_prompt_with_gemini(..., kinetic=True)` wraps the raw idea in a strict cinematographer-style instruction block:
  - Literal, physical descriptions only; no metaphors or abstractions.
  - Start in media res, use aggressive verbs (rushing, darting, whipping).
  - Explicit kinetic camera moves (whip pans, rapid tracking, FPV drone).
  - Single-scene, under ~50 words, and output is just the prompt line.
- Controlled via `VEO_EXPAND_PROMPT=1` so you can trade extra Gemini calls for richer, Veo-optimized prompts.
